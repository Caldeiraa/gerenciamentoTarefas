     (8) pergunte ao usuário se deseja atualizar mais algum documento; caso a resposta seja "Não", volte ao menu principal. Caso a resposta seja "Sim", volte ao menu de opções de entidades existentes ou permita que continue realizando a ação na entidade previamente selecionada

ESQUEMA DO PROJETO NO GITHUB (estrutura de módulos)
-----------------------------------------------------
- model: classes referentes às entidades do modelo relacional.
- conexion: módulo de conexão com o banco de dados.
- controller: módulo composto de classes responsáveis por controlar a criação dos objetos e transferir/alterar os dados para o banco de dados. (depende de model e conexion)
- utils: módulo composto de uma classe para auxiliar na criação dos menus, bem como de uma classe para controle e geração da tela de splash screen. (depende de conexion)
- reports: módulo responsável por gerar os relatórios a partir das consultas no MongoDB. (depende de conexion)
- principal: script principal responsável por unir e dar acesso ao restante do sistema. (usa controller, utils e reports)

FAQ
-----------------------------------------------------
- Podemos criar interface gráfica? Sim.
- Podemos manter o programa apenas no console sem interface gráfica? Sim, desde que tenha uma interface amigável e seja de fácil utilização.
- Podemos utilizar uma linguagem diferente? Sim, a linguagem em que se sentirem mais confortáveis, porém o projeto deve ser capaz de ser executado em ambiente Linux.
- Podemos usar algum componente, biblioteca ou funcionalidade que facilite a criação de consultas e alterações das coleções? NÃO. Você deverá criar as consultas e atualizações utilizando a linguagem nativa, apenas com uma biblioteca que permita a execução de comandos MongoDB (ou seja, sem ORM/ODM que abstraia as consultas).
- Podemos realizar o trabalho sem grupos? Prioritariamente, em grupo. É possível individualmente, desde que o aluno se responsabilize por desenvolver e entregar em tempo hábil.
- É possível trocar de grupo? Sim, até duas semanas antes da data de entrega.

ETAPA 2: Criação das Classes Principais
- Desenvolva as classes que representam as tabelas do tema (usar como referência os exemplos em src/model)
- Sempre que um objeto possui associação com outro, a classe deve ter como atributo uma instância do outro objeto, não apenas seu atributo (ver exemplos: src/model/itens_pedido.py e src/model/pedidos.py)
- Crie getters e setters para cada atributo
- Crie um método to_string para cada classe

ETAPA 3: Criação das Classes Controladoras
- Desenvolva as classes que realizam a interface entre os objetos da Etapa 2 e as tabelas/coleções da Etapa 1

- Em cada interface, realize a conexão antes de executar os comandos MongoDB
- Realize a concatenação dos atributos quando necessário
- Veja os exemplos existentes em src/controller
- Teste cada detalhe criado para saber se está funcionando corretamente

ETAPA 4: Criação dos Relatórios
